ANSWERS

a. No KV cache. It recomputes the full CONTEXT-token window from scratch on every generation
   step. The deciding lines are the docstring at 207-209 ("since there is no KV-cache...") and
   line 221: `window = np.array([t[-CONTEXT:] for t in tokens])` -- each of the gen_len iterations
   of the `for i in range(gen_len)` loop (line 220) re-slices the last CONTEXT tokens from the
   growing `tokens` list and re-runs the full forward pass `logits = model(x, depth_norm=d)`
   (line 225) over that whole window; nothing from step i-1's activations is reused at step i.
   Cost per well is therefore O(gen_len) full-context forward passes, not O(gen_len) incremental
   single-token steps -- explicitly called out in the MAX_GEN_LEN comment (line 46: "no-KV-cache so
   autoregressive generation is O(gen_len)").

b. It batches all realizations of one well into a single forward pass, not a loop of separate
   single-realization calls. Line 212 `B = n_realizations`; line 214 tiles the shared prime tokens
   to shape (B, 1) via `np.tile`; every tensor built inside the `for i in range(gen_len)` loop
   (window, dwindow, x, d, logits) carries that full batch dimension B, and the per-realization
   `for b in range(B)` loops (lines 230, 240, 243) only do post-hoc indexing/bookkeeping on
   already-batched model outputs -- the one `model(x, depth_norm=d)` call per step (line 225) is
   the only forward pass per step, covering all B realizations at once. The docstring (207-209)
   states this is deliberate: batching amortizes per-step Python/kernel-launch overhead across
   realizations, precisely because there is no KV-cache to amortize against instead.

c. The batch dimension at generation time is B = n_realizations. At the call site (lines 361-363)
   this is passed as N_REALIZATIONS = 5 (line 43), so tensors inside generate_batch have shape
   [5, ...] (e.g. `window`/`dwindow`: [5, CONTEXT]; `outputs`: [5, gen_len, n_features], line 219).
   This is per-well: the loop over test wells (line 350) is a plain Python loop across the 8 test
   wells, each well generating its own batch of 5 realizations independently -- wells are not
   batched together, only the 5 realizations within a well are.
